# 주택 수리 요청 프로세스 분석

네덜란드 임대 주택 기관의 **수리 요청 1,000건**을 분석해 처리 시간이 집중되는 구간과 요청 특성별 차이를 살펴봤습니다. 업무 경로와 시간 기록을 검토한 뒤, 개선을 우선 검토할 구간과 효과 검증에 필요한 지표를 제안했습니다.

분석 코드와 그래프, 개선안은 [분석 노트북](repair2_분석.ipynb)에서 확인할 수 있습니다.

## 주요 분석 결과

### 1. 현장 조사 시작 전 대기에 처리 시간 집중

시간 분석 대상 339건에서 **조사 일정 조율 완료 → 현장 조사 시작** 구간이 전체 경과 시간 합계의 **70.8%**를 차지했습니다. 이 구간의 대기 시간 중앙값은 **54.5시간**이며, **211건(62.2%)**에서 24시간을 초과했습니다.

### 2. E 유형에서 긴 처리 시간 관찰

전체 처리 시간 중앙값은 **B 유형 11.6시간, E 유형 160.4시간, P 유형 71.4시간**이었습니다. 내부 수리만 수행하고 시작·완료가 한 쌍인 E 유형 127건에서도 수리 시작 전 대기 중앙값은 **25.9시간**, 수리 업무 시간 중앙값은 **4.0시간**으로 나타났습니다.

### 3. Web·Letter 접수에서 긴 일정 조율 시간 확인

조사 일정 조율 업무(`ArrangeSurvey`)의 시작·완료 **809쌍 중 1시간을 초과한 194쌍(24.0%)**은 모두 Web·Letter 접수에서 발생했습니다. 담당자가 같은 경우에도 장시간 처리 사례가 있어, 채널이나 담당자 차이를 직접적인 원인으로 단정하기는 어렵습니다.

### 4. 예정 시각과 진행 상태를 기록하는 개선안 제안

현장 조사와 수리 착수의 **예정 시각·진행 상태·지연 사유**를 추가로 기록해 정상적인 예약 대기와 실제 지연을 구분하도록 제안했습니다. 원인이 확인된 구간부터 개선안을 적용하고, 예정 시각 초과율과 전체 처리 시간의 중앙값·P90으로 효과를 검증하는 방향입니다.

## 분석 과정

**전처리 → 업무 구성·경로 탐색 → 시간 정합성 검토 → 처리 시간·관련 요인 비교 → 개선안**

| 분석 | 확인한 내용 | 노트북 위치 |
| --- | --- | --- |
| 전처리·기초 탐색 | 자료형·결측값과 업무별 기록, 케이스별 업무 구성 | 1~5, 7단계 |
| 경로·날짜 검토 | 시작·종료 후보, 연도 혼재, 시작·완료 연결과 분석 표본 선정 | 8~9단계 |
| 업무 흐름·반복 | 주요 경로와 분기, 반복 업무, 단계별 기록률 | 10~11단계 |
| 시간·관련 요인 | 업무 시간·업무 간 대기, 담당자·수리 속성별 차이 | 12~14단계 |
| 개선안 | 우선 검토 대상, 추가 기록 항목과 효과 검증 지표 | 15단계 |

## 데이터 설명

- 원본: [repair2.csv](repair2.csv)
- 규모: **13,262개 이벤트 × 13개 칼럼**, 요청 **1,000건**, 업무 **13종류**
- 한 행은 업무의 이벤트 기록입니다. 같은 작업의 시작과 완료가 각각 기록될 수 있어 이벤트 수와 업무 수행 횟수를 구분했습니다.
- `originator`에는 시스템을 포함해 16종류의 식별자가 기록되어 있습니다. 이름만으로 실제 담당자의 역할이나 소속을 구분하지 않았습니다.

<summary>13개 칼럼 설명</summary>

| 칼럼 | 한글 명칭 | 설명 및 기록값 |

| `caseID` | 수리 요청 번호 | 하나의 요청을 구분하는 식별자 |

| `objectKey` | 대상 식별 번호 | 수리 대상과 관련된 키. 정확한 식별 대상은 미확인 |
| `RepairInternally` | 내부 수리 여부 | 원본 표기 `TRUE` / `FALSE` |
| `EstimatedRepairTime` | 예상 수리 시간 | `60`, `120`, `160`, `220`, `240`, `360`, `480`. 단위·산정 범위는 미확인 |
| `RepairCode` | 수리 코드 | `1`, `2`, `3`, `4`. 코드별 의미는 미확인 |
| `RepairOK` | 수리 정상 여부 | 원본 비결측값은 `TRUE`만 존재. 결측을 실패로 해석하지 않음 |
| `date` | 기록 날짜 | 이벤트 날짜 |
| `time` | 기록 시각 | `date`와 결합해 분석용 `timestamp` 생성 |

표의 값은 원본 CSV 기준입니다. Python에서 변환한 불리언 값은 `True` / `False`로 표시됩니다. 요청 속성은 일부 이벤트에만 기록될 수 있어 이벤트별 결측과 요청 전체의 미기록·상충값을 구분했습니다.

## 분석 시 유의사항

- 날짜에 1905·1970·2020~2022년이 혼재해 실제 발생 날짜를 임의로 보정하지 않았습니다.
- 업무 구성은 전체 1,000건, 케이스 전체 시간은 일반 경로 927건 중 조건을 충족한 339건(36.6%)을 사용했습니다. 개별 업무 시간 비교는 별도 기준을 충족한 시작·완료 쌍을 사용하므로 분석별 표본이 다릅니다.
- 기록상 대기가 실제 운영 지연을 의미하는 것은 아닙니다. 시간 분석은 탐색적 결과이며, 관찰된 차이를 원인이나 개선 효과로 확정하지 않았습니다.

## 사용 기술 및 실행 방법

**Python · pandas · Matplotlib · Plotly · JupyterLab**

저장소를 내려받아 CSV와 노트북을 같은 폴더에 둔 뒤 실행합니다.

```bash
python -m pip install pandas matplotlib plotly jupyterlab
python -m jupyterlab
```
