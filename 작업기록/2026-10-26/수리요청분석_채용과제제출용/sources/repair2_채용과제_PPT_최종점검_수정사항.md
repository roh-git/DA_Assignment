# 수리 요청 프로세스 분석 PPT 최종 수정 가이드

**검토 대상** `repair2_채용과제_분석결과.pdf` 13페이지 버전  
**목적** 채용담당자가 별도 설명 없이도 분석의 의도와 근거 및 개선 제안을 이해하도록 수정  
**수정 원칙** 13장 구성과 기존 디자인 유지 · 정확성 우선 · 새로운 분석보다 설명과 가독성 보완

## 1. 최종 평가와 수정 우선순위

자료의 전체적인 논리 구조는 적절함

**분석 질문 → 데이터 검증과 전처리 → 업무 흐름 및 반복 분석 → 업무 시간과 대기 구간 비교 → 관련 특성 분석 → 개선 제안 → 효과 검증**으로 이어지는 흐름을 유지할 것

| 중요도 | 페이지 | 필요한 수정 | 이유 |
|---|---|---|---|
| **필수** | **03 데이터 개요** | `16명 담당자`를 `업무 수행 주체 16종`으로 수정하고 업무 쌍 선별 설명 간소화 | 시스템 기록을 사람으로 잘못 설명할 위험 |
| **필수** | **10 수리 유형별 비교** | 동일 `InternRepair` 조건의 B·E·P 대기 시간 수치와 표본 수를 함께 제시 | E 유형 비교 결론의 근거 명시 |
| **필수** | **13 효과 검증** | 조사와 수리의 예정 시각 초과 지표를 구분하고 최종 결론 강화 | 무엇을 측정할지와 왜 측정하는지 명확화 |
| 권장 | 04 날짜 검증 | 860·226·636이라는 수치가 의미하는 검증 질문을 쉬운 언어로 표현 | 이번 분석의 중요한 판단 과정 전달 |
| 권장 | 07 업무 시간 비교 | 중앙값만으로 인과관계나 관련성 부재를 결론 내리지 않도록 표현 | 과장 없는 통계 해석 |
| 권장 | 12 개선 방안 | 추상적인 조치 표현을 행동 중심으로 간결하게 수정 | 제안의 실행 가능성 전달 |
| 전체 | 03·04·08·10·13 등 | 핵심 제한사항과 표본 수의 시인성 확보 | PPT 화면에서 읽히도록 개선 |

> 표본 수와 시간 수치는 기존 분석 노트북과 발표자료에 기록된 결과를 기준으로 작성했으며 새로운 인과 검증이나 운영 효과를 주장하지 않음

## 2. 필수 수정 상세

### 03 | 데이터 개요와 전처리

**문제**

`기본 확인: 13개 업무 · 16명 담당자`는 실제 사용자와 시스템·자동화 주체를 구분하지 않는 표현임

**교체 문구**

```text
기본 확인: 업무 종류 13개 · 업무 수행 주체 16종(시스템 기록 포함)
```

**현재 설명**

```text
1:1 연결 후보 3,631쌍 → 시간 비교 가능 3,627쌍 → 보수적 조건 충족 3,151쌍
```

**교체 권장 문구**

```text
업무 시작과 완료가 각각 1회 기록된 3,631쌍 중
시각 조건을 충족한 3,151쌍의 업무 수행 시간을 분석
```

**남길 기준**

- 시작과 완료 시각을 연결한 기록만 업무 소요 시간 계산에 활용
- 시간 분석에 사용한 기록은 모두 1970년으로 표기되어 있어 실제 연도의 정확성은 미확인
- 중간 검증 단계인 3,627쌍과 연도 불일치에 따른 시간 역전은 04페이지에서 설명
- 전체 1,000건과 일반 경로 시간 분석 339건을 혼동하지 않도록 분리 표기

### 10 | 수리 유형별 비교

**문제**

`같은 InternRepair 업무로 좁혀도 E 유형의 긴 대기가 유지됐다`는 문구가 있지만 화면에는 E 유형 127건의 값만 크게 제시되어 있음

**추가할 비교 근거**

| `InternRepair` 단독 및 시작·완료 1:1 연결 | 건수 | 수리 시작 전 대기 중앙값 |
|---|---:|---:|
| B 유형 | 25건 | 0.0시간 |
| **E 유형** | **127건** | **25.9시간** |
| P 유형 | 8건 | 0.9시간 |

**추천 화면 구성**

- 왼쪽의 케이스 전체 처리 시간 B 11.6시간 / E 160.4시간 / P 71.4시간 그래프는 그대로 유지
- 오른쪽 상단에는 수리 유형별 `Survey complete → 첫 수리 start` 대기 시간 E 25.2시간 비교를 유지
- 오른쪽 하단의 E 유형 25.9시간과 실제 `InternRepair` 4.0시간 표시를 축소해 위 B·E·P 비교표를 배치
- 우측 하단 작은 문구로 `P 유형은 8건으로 표본이 적어 해석에 주의` 추가

**교체 권장 결론**

```text
E 유형은 전체 처리 시간과 수리 시작 전 대기가 길게 기록됨
같은 InternRepair 업무만 수행한 요청끼리 비교해도 E 유형의 긴 대기가 관찰됨
다만 수리 유형이 긴 대기의 원인이라고 단정할 수는 없음
```

**구간 용어 주의**

- `첫 수리 start → RepairReady complete`는 수리 시작 이후의 전체 경과 시간
- `InternRepair start → complete`는 실제 해당 업무 기록의 수행 시간
- 서로 다른 구간을 모두 `실제 수리 시간`으로 표기하지 않도록 구분
- 개별 구간 중앙값을 더해 케이스 전체 처리 시간 중앙값으로 표현하지 않음

### 13 | 효과 검증과 분석 한계

**문제**

`예정 초과 미착수율`이 조사 일정과 수리 일정에서 각각 무엇을 뜻하는지 불명확함

**지표 표기 통일**

| 개선 대상 | 지표 명칭 | 측정하려는 변화 |
|---|---|---|
| 현장 조사 일정 | **조사 예정 시각 초과 미착수율** | 예정 시각이 지났으나 현장 조사를 시작하지 못한 요청의 비율 |
| E 유형 수리 착수 | **수리 예정 시각 초과 미착수율** | 예정 시각이 지났으나 수리 업무를 시작하지 못한 요청의 비율 |
| 조사·수리 진행 | 착수 지연 시간 | 예정 시각보다 실제 시작이 얼마나 늦었는지 |
| Web·Letter 조사 일정 조율 | `ArrangeSurvey` 1시간 초과율 및 P90 | 장시간 업무 처리 사례의 변화 |
| 최종 성과 | **케이스 전체 처리 시간 중앙값 및 P90** | 부분 개선이 요청 전체의 완료 기간 단축으로 이어졌는지 |

**지표 설명을 자료에 넣는다면**

```text
예정 시각 초과 미착수율(%) =
(조회 시점에 예정 시각이 지났지만 아직 시작하지 않은 요청 수
 / 조회 시점까지 시작할 예정이었던 전체 요청 수) × 100
```

**개선 전후 비교 시 주의**

- 예정 시각이 아직 지나지 않은 요청은 분모에서 제외
- 실제 착수가 이미 이루어진 요청은 미착수 건수에서 제외
- 조사·수리 예정 시각은 기존 로그에 없으므로 **신규 수집 후** 해당 지표를 계산
- 기존 1970년 날짜의 정확성이 검증되지 않아 신뢰할 수 있는 시각 기록으로 새로운 기준을 먼저 마련
- 수리 유형과 접수 채널의 구성 차이를 살펴 개선 효과의 비교 가능성 검토

**슬라이드 하단 교체 권장 결론**

```text
조사 시작 전 대기는 전체 처리 시간에서 큰 비중을 차지했지만 실제 지연 원인은 확인되지 않음
예정 시각과 지연 사유를 추가로 기록한 뒤 개선 전후의 대기 시간과 전체 완료 시간을 함께 비교
```

## 3. 권장 보완 상세

### 02 | 분석 목적과 검토 질문

**현재 장점** 최초 검토 질문과 분석 방법이 서로 대응되어 있어 분석의 출발점을 이해하기 쉬움

**유지할 점** E 유형과 Web·Letter라는 세부 발견을 초기부터 알고 있던 확정 가설처럼 제시하지 않음

**표현 원칙**

- `검토 질문`이라는 명칭 유지
- 초기 문제의식과 탐색 과정에서 새로 발견한 질문을 구분
- 처음부터 인과관계를 검증한 것처럼 보이는 `입증` 등의 용어 사용 지양

### 04 | 날짜 검증과 처리 결정

**현재 장점** 1970년을 2020년으로 바꾸지 않은 판단을 데이터 근거와 연결함

**수정 목표** 큰 수치를 제시하는 것에서 끝나지 않고 왜 의심했는지 함께 알려주기

| 현재 수치 | 추천 보조 설명 |
|---|---|
| 860/860행 | 2020~2022년 기록의 날짜가 CSV 행 순서대로 하루씩 증가해 실제 업무 날짜인지 의문이 발생 |
| 226/3,627쌍 | 업무가 시작되기 전에 완료된 것으로 나타나는 시간 역전 기록이 존재 |
| 636개 이벤트 | 같은 요청에서 연도가 다른 기록과 시각이 일치하는 사례가 있으나 원래 날짜를 확정할 근거는 아님 |

**판단 과정은 아래 순서로 유지**

1. 원본에서 비정상적인 연도 혼재 발견
2. 행 순서와 날짜 증가 패턴 및 시작·완료 시간 역전 확인
3. `1970 → 2020` 치환과 해당 행 전체 삭제의 타당성 검토
4. 원래 날짜를 복원할 근거가 없어 두 대안을 보류
5. 업무 흐름은 원본 전체 1,000건을 유지하고 시간 계산은 339건 등 조건별 표본을 사용

**주의** 1970년으로 기록된 339건을 `정확한 날짜가 확인된 사례`로 표현하지 않음

### 05 | 업무 흐름 분석

**유지 권장** 영문 원본 업무명과 한국어 설명을 함께 표시한 방식이 좋아

**가독성 확인**

- 일반 927건과 예외 73건의 분기가 한눈에 보이도록 선의 대비 유지
- 예외 경로와 `InformClientWrongPlace`를 화살표로 연결
- 실제로 고정된 순서가 아닌 후반 업무는 구조 요약임을 표시

### 06 | 반복 작업 분석

**유지 권장** 단일·복합 업무와 동일 업무의 반복 기록을 분리한 구성

**간결화 권장**

```text
일반 경로 927건 중 복합 수리 91건이 기록됨
InternRepair가 반복된 사례 38건을 확인했으나 반복 원인과 재작업 여부는 알 수 없음
```

29건의 시간순 검토 조건은 작은 글씨라도 확인 가능하게 유지

### 07 | 개별 업무 시간과 전체 시간 비교

**현재 발견** `ArrangeSurvey` 1시간 초과 75건과 이하 264건에서 전체 처리 시간 중앙값은 각각 78.2시간과 77.2시간

**추천 표현**

```text
ArrangeSurvey 처리 시간이 1시간을 넘는 요청에서도
전체 처리 시간 중앙값은 비교 집단과 큰 차이를 보이지 않음
따라서 업무 자체의 시간 외에 업무 사이의 대기도 별도로 확인
```

중앙값이 비슷하다는 이유만으로 `전체 처리 시간과 관련이 없다`고 단정하지 않음

### 08~09 | 전체 처리 시간 및 주요 대기 구간

**유지 권장 수치**

- 전체 처리 시간 중앙값 77.3시간
- `ArrangeSurvey complete → Survey start` 구간 합계 비중 70.8%
- 대기 중앙값 54.5시간 및 P90 195.7시간
- 24시간 초과 211/339건으로 62.2%

**표현 주의**

- 70.8%는 339건에서 구간별 기록 시간 합계가 차지하는 비중
- 절감 가능 비율이나 확인된 병목 손실률로 표현하지 않음
- 24시간 초과 기준은 분석자가 설정한 탐색 기준이지 운영상의 SLA가 아님
- 예정된 조사 날짜가 없으므로 정상 예약 대기와 비정상적인 착수 지연을 구분할 수 없음

### 11 | 접수 채널과 담당자 분석

**핵심 발견 유지**

- `ArrangeSurvey` 장시간 처리 194건은 모두 Web·Letter에서 관찰
- Web 중앙값 119분과 Letter 중앙값 5분은 서로 다른 분포를 의미
- 시작·완료 담당자가 다른 경우 중앙값 332분과 동일한 경우 4분을 비교
- 담당자가 같은 Web·Letter에서도 1시간 초과 89건이 발생

**주의** 담당자 기록 차이를 실제 인수인계나 작업자 역량 차이로 단정하지 않음

### 12 | 개선 방안

**현재 장점** 문제와 수집할 정보 및 가능한 운영 조치가 1:1로 연결돼 있음

**추천 문구 조정**

| 개선 대상 | 기존 추상적 표현 대신 쓸 문장 |
|---|---|
| 조사 시작 전 대기 | 조사 예정 시각을 기록하고 예정 시간을 넘긴 미착수 요청을 확인한 뒤 사유에 따라 일정 조정 |
| E 유형 수리 시작 전 대기 | 조사 완료 이후의 진행 상태와 수리 예정 시각을 기록하고 반복적인 지연 사유가 확인된 단계부터 개선 |
| Web·Letter 일정 조율 | 채널별 업무 진행 상태와 시작·완료 담당자 기록 차이를 확인하고 실제 지연이 나타난 처리 절차를 점검 |

**주의** 아직 확인하지 않은 자재 확보 문제나 인력 부족을 개선의 확정 원인으로 제시하지 않음

## 4. 공통 디자인 및 가독성 가이드

### 기존 디자인에서 유지할 것

- 흰색 배경과 청록색 강조 및 회색 보조색의 통일감
- 각 페이지 상단의 분석 단계명
- 발견한 내용을 문장형으로 전달하는 메인 제목
- 한 슬라이드에 하나의 핵심 발견을 중심으로 배치한 구조
- 영문 `taskID`와 쉬운 한국어 설명 병기

### 수정할 것

| 항목 | 작업 지침 |
|---|---|
| 핵심 수치 | 제목이나 그래프 옆에서 가장 먼저 눈에 들어오도록 크기와 대비 조정 |
| 표본 수 | `339건`, `809건`, `127건`처럼 서로 다른 분석 범위를 차트 제목에 표시 |
| 중요 주석 | 날짜 미검증 및 표본 제한처럼 결론 해석에 필요한 내용은 보이는 크기로 확대 |
| 일반 출처 표기 | 하단으로 유지하되 본문 핵심 메시지와 시각적으로 분리 |
| 복잡한 표 | 핵심 숫자만 본문에 남기고 선정 조건과 상세 계산은 노트북·보고서로 이동 |
| 차트 레이블 | 단위가 분인지 시간인지 모든 차트에서 명확히 표시 |
| 여백 | 표와 차트 및 하단 해석 문장 사이 간격을 확보하고 텍스트가 꽉 차 보이지 않게 조정 |

**크기 참고** 16:9 PPT 기준 본문 16~20pt를 우선 검토하고 차트 레이블 14pt 이상 및 중요한 주석 11~12pt를 권장

**텍스트 작성 기준**

- `데이터가 말하는 사실 → 그 결과의 해석 → 다음 분석이나 제안` 순서
- 문장 안의 쉼표는 나열하는 경우에만 사용
- 문장 끝 마침표 생략
- 전문 용어는 처음 등장할 때 설명
- 확인된 사실과 가설 및 추가 수집이 필요한 정보를 구분
- `확정`, `입증`, `원인`, `병목 손실`처럼 지나친 확신을 주는 표현은 근거가 있을 때만 사용
