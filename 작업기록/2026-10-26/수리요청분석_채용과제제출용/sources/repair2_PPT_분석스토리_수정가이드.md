# 수리 요청 프로세스 분석 PPT 스토리 및 수정 가이드

> 목적: 채용담당자가 발표자의 설명 없이도 **왜 분석했는지 → 무엇을 확인했는지 → 결과를 어떻게 해석했는지 → 무엇을 개선할지 → 성과를 어떻게 평가할지** 이해할 수 있도록 기존 10장 PPT를 수정

## 1. 전체 전달 원칙

**발표의 핵심 이야기**

수리 요청 1,000건의 업무 기록으로 현재 업무 흐름을 파악한 뒤 업무별 처리 시간과 업무 사이의 대기를 구분해 분석함

분석 가능한 일반 경로 339건에서는 현장 조사를 시작하기 전 대기가 전체 기록상 처리 시간 합계의 70.8%를 차지했으며 E 유형의 수리 착수 전 대기와 Web·Letter 접수의 장시간 처리도 추가로 관찰됨

다만 이러한 시간이 모두 불필요한 지연인지는 확인되지 않아 예정 시각과 지연 사유를 추가로 기록하고 실제 원인에 따라 개선할 것을 제안함

### 페이지 공통 작성 방식

1. **구분명**: 데이터 전처리 · 프로세스 구조 · 처리 시간 분석처럼 페이지의 역할을 표시
2. **제목**: 차트에서 확인한 핵심 사실을 한 문장으로 제시
3. **분석 의도**: 왜 이 분석을 했는지 1문장으로 설명
4. **근거**: 분석 대상과 단위가 포함된 표 또는 시각화 제시
5. **해석**: 확인된 사실과 아직 확인되지 않은 원인을 구분해 1~2문장으로 정리
6. **연결**: 다음 페이지에서 무엇을 추가로 살펴볼지 자연스럽게 연결

**주의**: 매 페이지에 여섯 항목을 모두 별도 박스로 넣을 필요는 없음

### 과제 평가기준 대응

| 평가 요구사항 | 대응 페이지 |
|---|---|
| 기본 분석 및 데이터 전처리 | 01~02 |
| 현재 수리 프로세스 설명 | 03 |
| 병목 후보 및 반복 작업 분석 | 04~06 |
| 케이스 소요 시간 관련 요소와 근거 | 07~08 |
| 프로세스 개선 방안 | 09 |
| 효과 검증 및 분석 한계 | 10 |

## 2. 최종 PPT 10장 구성

### 01. 분석 개요

**메인 제목**: 수리 요청 프로세스 분석 및 개선 제안

- **분석 의도**: 수리 요청이 어떤 흐름으로 처리되며 처리 시간이 길어지는 구간이 어디인지 확인
- **내용**: 전체 1,000건 · 일반 경로 927건 · 시간 분석 대상 339건
- **역할**: 데이터에서 발견한 문제를 개선 제안으로 연결하는 발표임을 안내
- **시각화**: 표지와 핵심 분석 규모 표시
- **다음 페이지 연결**: 시간 분석에 사용할 기록이 신뢰할 수 있는지 먼저 검토

### 02. 데이터 개요 및 전처리

**메인 제목**: 데이터 품질을 점검하고 분석 목적에 따라 대상을 구분했다

- **분석 의도**: 업무 경로 분석과 시간 분석에 서로 다른 데이터 조건이 필요한지 확인
- **접근**: 전체 13,262개 이벤트의 결측과 날짜 분포 확인
- **결과**: 업무 경로는 전체 1,000건으로 파악하고 시간 분석은 모든 이벤트 시각이 기록되어 1970년으로 표시된 일반 경로 339건을 사용
- **해석**: 1905년 및 2020~2022년 기록 등 이상 날짜의 원인이 확인되지 않아 임의 보정하지 않음
- **시각화**: 전체 → 경로 분석 전체 유지 / 시간 분석 후보 402건 → 일반 경로 339건 선별 흐름도
- **주의**: 1970년 기록이 실제 날짜라는 뜻은 아니며 시간 결과는 탐색적으로 해석
- **다음 페이지 연결**: 선별 기준을 밝힌 뒤 실제 업무 진행 흐름 파악

### 03. 프로세스 구조 분석

**메인 제목**: 수리 요청은 일반 경로와 예외 경로로 나뉘며 수리 업무도 분기된다

- **분석 의도**: 시간과 반복 작업을 분석하기 전에 수리 요청의 일반적인 처리 구조 확인
- **접근**: 케이스별 수행 업무와 종료 경로 파악
- **결과**: 일반 경로 927건과 예외 경로 73건 확인
- **시각화**: 전체 프로세스 흐름도 또는 Sankey 다이어그램
- **원본 업무명 설명**: `MakeTicket` 수리 요청 등록 / `ArrangeSurvey` 현장 조사 일정 조율 / `Survey` 현장 조사 / `InternRepair` 내부 수리 / `ImmediateRepair` 즉시 수리 / `ExternRepair` 외부 수리
- **주의**: 업무 분기와 복합 수행이 있어 모든 케이스가 하나의 고정 순서로 진행된다고 표현하지 않음
- **다음 페이지 연결**: 실제 업무 구성에서 복합 수행과 반복 기록이 있는지 확인

### 04. 반복 작업 분석

**메인 제목**: 일부 요청에서 여러 수리 업무와 동일 업무의 반복 기록이 관찰됐다

- **분석 의도**: 업무를 불필요하게 반복하는 사례가 있는지 탐색
- **접근**: 케이스별 수리 업무 종류 및 `InternRepair` 반복 기록 확인
- **결과**: 일반 경로 927건 중 복합 수리 91건 / `InternRepair` 반복 기록 38건
- **시각화**: 단일·복합 수리 구성 비율과 반복 작업의 실제 시작·완료 기록 예시
- **해석**: 동일 업무가 여러 번 기록된 사실은 확인되지만 하자 재작업이나 불필요한 반복이라는 근거는 부족
- **주의**: 시간순 추가 검토 29건은 실제 선별 조건을 밝혀야 함
- **다음 페이지 연결**: 반복 여부뿐 아니라 전체 처리 시간 중 어느 구간에 시간이 집중되는지 확인

### 05. 전체 처리 시간 분석

**메인 제목**: 조사 일정 조율 완료 후 현장 조사 시작까지의 대기가 가장 큰 비중을 차지했다

- **분석 의도**: 실제 업무 수행과 다음 업무를 기다리는 시간을 구분해 우선 검토할 구간 찾기
- **접근**: 일반 경로 시간 분석 대상 339건의 처리 시간을 주요 구간으로 나누어 합계 비중 계산
- **결과**: `ArrangeSurvey complete → Survey start` 구간은 전체 기록상 처리 시간 합계의 70.8% / 케이스별 전체 처리 시간 중앙값 77.3시간
- **시각화**: 전체 업무 흐름에서 해당 구간을 강조한 흐름도와 구간별 시간 비중
- **해석**: 긴 경과 시간이 확인됐다는 뜻이지 70.8% 전체가 실제 병목이나 절감 가능한 시간이라는 뜻은 아님
- **다음 페이지 연결**: 이 구간에서 긴 대기가 일부 케이스에만 발생하는지 전체적으로 나타나는지 확인

### 06. 주요 대기 구간 상세 분석

**메인 제목**: 현장 조사 시작 전 대기는 절반 이상에서 하루를 초과했다

- **분석 의도**: 70.8%라는 전체 비중이 어떤 대기 시간 분포에서 나타나는지 확인
- **접근**: `ArrangeSurvey complete → Survey start`의 케이스별 대기 시간 구간 집계
- **결과**: 중앙값 54.5시간 / P90 195.7시간 / 24시간 초과 211건(62.2%)
- **시각화**: 대기 시간 구간별 건수 가로 막대그래프
- **용어 설명**: P90은 전체 요청의 약 90%가 해당 시간 이하인 경계값
- **해석**: 긴 대기는 확인되지만 약속된 조사 날짜가 없어 정상적인 예약 대기인지 실제 일정 지연인지 구분할 수 없음
- **다음 페이지 연결**: 전체 처리 시간 차이가 수리 유형에 따라 달라지는지 확인

### 07. 수리 유형별 비교 분석

**메인 제목**: E 유형의 전체 처리 시간이 가장 길었고 수리 착수 전 대기도 상대적으로 길었다

- **분석 의도**: 케이스 전체 처리 시간이 특정 수리 유형과 관련이 있는지 확인
- **접근**: B·E·P 유형의 전체 처리 시간과 조사 완료 후 수리 착수 전 대기 비교
- **결과**: 전체 처리 시간 중앙값 B 11.6시간 / E 160.4시간 / P 71.4시간
- **추가 검토**: E 유형의 수리 시작 전 대기 중앙값 25.2시간 / `InternRepair` 단독 시작·완료 1:1 케이스 127건에서는 대기 25.9시간과 실제 수리 업무 4.0시간
- **시각화**: 수리 유형별 전체 처리 시간 막대그래프와 E 유형 추가 검토 결과
- **해석**: E 유형에서 긴 대기가 관찰되지만 수리 유형 자체가 지연의 원인이라는 결론은 아님
- **주의**: B·E·P의 구체적 의미가 원본에서 확인되지 않았다면 코드 그대로 표기 / 전체 처리 시간 339건과 구간 분석 338건은 다른 표본
- **다음 페이지 연결**: 수리 유형 외에 접수 방식과 업무 담당자 관련 기록도 확인

### 08. 접수 채널 및 담당자 분석

**메인 제목**: Web·Letter 접수에서 조사 일정 조율 업무의 장시간 처리 사례가 집중됐다

- **분석 의도**: `ArrangeSurvey` 업무 자체의 처리 시간이 접수 채널이나 담당자 차이 여부와 관련되는지 확인
- **접근**: 채널별 `ArrangeSurvey start → complete` 처리 시간 비교 / 시작·완료 담당자 동일 여부 비교
- **결과**: 1시간 초과율 Web 52.7% / Letter 48.6% / Phone·Personal 0%
- **추가 결과**: 처리 시간 중앙값 Web 119분 / Letter 5분 / Phone 3분 / Personal 4분
- **담당자 비교**: 동일 담당자 704건 중앙값 4분 / 다른 담당자 105건 중앙값 332분
- **시각화**: 채널별 1시간 초과율과 담당자 동일 여부별 처리 시간
- **해석**: Web과 Letter의 분포도 다르며 담당자 차이만으로 긴 처리 시간을 설명할 수 없음
- **주의**: 시작·완료 담당자 차이를 실제 인수인계 발생 또는 지연 원인으로 단정하지 않음 / 앞선 `ArrangeSurvey → Survey` 대기와는 다른 구간
- **다음 페이지 연결**: 분석으로 찾은 세 가지 검토 대상에 어떤 개선안을 적용할지 제안

### 09. 프로세스 개선 방안

**메인 제목**: 긴 대기와 장시간 처리 구간에서 실제 지연 원인을 확인한 뒤 개선한다

- **분석 의도**: 발견한 현상을 실제 개선으로 연결하되 확인되지 않은 원인을 단정하지 않기
- **시각화**: 문제 → 추가 기록 → 검토할 운영 조치의 3행 비교표

| 우선 검토 대상 | 확인된 현상 | 추가로 확보할 정보 | 개선 방향 |
|---|---|---|---|
| 조사 시작 전 대기 | 전체 처리 시간 합계의 70.8% | 조사 예정 시각 · 담당자 배정 상태 · 지연 사유 | 예정 시각을 넘긴 미착수 건 확인 후 일정 조정 검토 |
| E 유형 수리 시작 전 대기 | 중앙값 25.2시간 | 수리 예정 시각 · 수리 착수 전 진행 상태 · 지연 사유 | 반복 지연 원인 확인 후 해당 절차 개선 검토 |
| Web·Letter `ArrangeSurvey` 내부 | 장시간 처리 사례 집중 | 채널별 진행 상태 · 시작/완료 담당자 차이 사유 | 지연이 확인된 세부 처리 절차 점검 |

- **해석**: 우선순위는 검토 순서이지 절감 효과가 입증된 순서가 아님
- **다음 페이지 연결**: 개선안을 적용했을 때 무엇을 측정해 효과를 판단할지 제시

### 10. 성과 검증 계획 및 분석 한계

**메인 제목**: 실제 일정 지연이 줄었는지 확인하고 전체 수리 완료 시간으로 효과를 검증한다

- **분석 의도**: 업무 일부가 빨라진 것이 아니라 요청 전체의 처리 기간이 단축됐는지 확인
- **핵심 구성 ① 추가 기록**: 조사·수리 예정 시각과 실제 시작 시각 및 지연 사유 기록
- **핵심 구성 ② 지연 확인**: 예정 시각을 넘겼는데 아직 시작되지 않은 요청의 비율과 실제 착수 지연 시간 확인
- **핵심 구성 ③ 성과 검증**: 개선 전후 조사 시작 전 대기 시간 · 수리 시작 전 대기 시간 · `ArrangeSurvey` 장시간 처리율 비교
- **최종 결과 지표**: 케이스별 전체 처리 시간 중앙값 및 P90의 개선 전후 비교
- **시각화**: 추가 기록 → 지연 원인 확인 → 시범 개선 → 구간 및 전체 처리 시간 재측정의 간결한 흐름도
- **분석 한계**: 원본의 1970년 날짜 정확성 미검증 / 조사·수리 예정 시각 없음 / 실제 지연 원인 미확인 / 일부 업무 완료 시각 부재
- **주의**: 현재 데이터로 절감률을 확정하지 않고 신뢰할 수 있는 신규 시간 기록을 확보해 비교
- **표현 원칙**: 계산식과 `조회 시각 t` 같은 기술적 설명은 발표 본문 대신 노트북 또는 부록에 배치

- [ ] 결과를 읽는 데 필요한 원본 업무명은 한국어로 한 번 설명했는가
- [ ] 관찰된 관련성과 실제 원인 또는 인과관계를 구분했는가
- [ ] 각 분석 결과가 다음 분석 또는 개선 제안으로 연결되는가
- [ ] 9페이지의 모든 개선안이 앞선 분석 결과와 대응되는가
- [ ] 10페이지에 구간별 지표와 전체 처리 시간 지표가 함께 있는가
- [ ] 1970년 날짜 정확성 및 예정 시각 미기록의 한계를 명시했는가
- [ ] 처음 보는 사람이 발표자의 설명 없이도 1~10페이지를 이해할 수 있는가

## 4. 제작 시 표현 기준

- **분석 방법만 제시하지 말고 목적과 결과를 함께 제시**
- **한 슬라이드에 핵심 메시지 하나만 배치**
- **상단 구분명은 간결하게 표현**: 개요 · 데이터 전처리 · 프로세스 구조 분석 · 반복 작업 분석 · 처리 시간 분석 · 수리 유형별 분석 · 개선 방안 · 효과 검증
- **기술적인 계산식은 꼭 필요할 때만 사용**
- **데이터로 확인한 현상과 확인되지 않은 가설을 명확하게 구분**
- **분석을 시작할 때부터 결론을 알고 있었던 것처럼 설명하지 말고 관찰 결과를 바탕으로 추가 분석했다는 과정을 유지**
