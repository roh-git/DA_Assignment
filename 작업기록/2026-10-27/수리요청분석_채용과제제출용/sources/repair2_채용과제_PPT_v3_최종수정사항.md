# 수리 요청 프로세스 분석 발표자료 — 최종 수정사항

> **검토 대상** `repair2_채용과제_분석결과(3).pdf` · 총 13페이지
>
> **수정 목표** 분석 근거를 유지하면서 처음 보는 채용담당자가 핵심 내용을 빠르게 이해할 수 있도록 구성
>
> **전체 판단** 큰 구조와 디자인은 유지 · **4페이지와 13페이지 우선 정리** · 10페이지 표본 구분만 소폭 보완

## 1. 수정 우선순위

| 우선순위 | 페이지 | 조치 | 이유 |
|---|---|---|---|
| 1 | 13 효과 검증과 분석 한계 | 산출식과 한계 항목 압축 | 마지막 페이지에서 핵심 성과 지표가 눈에 띄어야 함 |
| 2 | 4 날짜 검증과 처리 결정 | 검증 근거를 2개 중심으로 재배치하고 하단 중복 삭제 | 핵심 의사결정이 세부 수치에 묻힘 |
| 3 | 10 수리 유형별 비교 | 25.2시간과 25.9시간의 표본 차이 명시 | 비교 기준을 혼동할 가능성 |
| 4 | 1·2·5·7·8·9·11·12 | 필요한 경우 반복 해석만 삭제 | 현재 차트 및 시각적 구성은 대체로 유지 가능 |

**반드시 유지할 핵심 메시지**

- 날짜의 실제 정확성이 확인되지 않아 1970년을 2020년으로 일괄 변경하지 않음
- 업무 흐름 1,000건 · 개별 업무 시간 3,151쌍 · 일반 경로 시간 분석 339건으로 분석 범위를 구분
- `ArrangeSurvey complete → Survey start`가 분석 대상 339건의 기록상 전체 시간 합계 중 70.8%를 차지
- E 유형의 긴 수리 전 대기와 Web·Letter의 장시간 `ArrangeSurvey` 사례를 관련 현상으로 제시
- 정상적인 예약 대기와 실제 운영 지연은 아직 구분할 수 없음

## 2. 페이지별 수정 지시

### 1페이지 — 표지

**조치: 유지**

- 다크 배경과 주요 수치 3개 카드의 시각적 계층 유지
- `SCOPE 02 · 정상 경로`는 다른 슬라이드의 용어와 맞춰 **`일반 경로`**로 교체
- 표본 339건은 확정된 정확한 날짜가 아니라 분석 조건을 충족한 기록임을 본문 다른 페이지에서 설명

### 2페이지 — 분석 목적과 검토 질문

**조치: 유지**

- 질문 4개와 비교 방법의 대응 구조 유지
- 하단 `해석 / 해석 시 주의` 영역이 공간을 차지한다면 1줄로 축소

**짧은 교체 문구**

> 분석 질문은 수행 과정의 판단을 정리한 것이며 E 유형과 특정 채널 비교는 탐색 후 추가

### 3페이지 — 데이터 개요와 전처리

**조치: 유지 · 작은 용어 수정만**

- 1,000건 / 3,151쌍 / 339건의 구분은 핵심이므로 삭제하지 않음
- `16종`에 시스템 기록이 포함된 설명 유지
- 분석 대상 선별 과정과 날짜 오류 이유는 4페이지에서 설명하므로 본 페이지에 더 추가하지 않음
- 하단 두 박스가 중복으로 느껴진다면 다음 한 줄로 통합

**축약 문구**

> 업무 흐름은 전체 1,000건으로 확인하고 시간은 조건을 충족한 표본에서만 탐색적으로 계산

### 4페이지 — 날짜 검증과 처리 결정 **[중점 수정]**

**현재 문제**

- `860/860행`, `226/3,627쌍`, `636개 이벤트`를 동시에 강조하면서 수치의 의미를 이해해야 다음 판단을 읽을 수 있음
- 오른쪽 `원본 유지` 결론과 하단 `날짜 복원 근거가 없어 원본 유지`가 반복됨

**권장 구조**

1. 상단 제목 유지: **`날짜 이상을 확인했지만 1970년을 2020년으로 바꾸지는 않았다`**
2. 왼쪽은 아래 **두 가지 핵심 검증 근거**를 크게 배치
3. 오른쪽에는 **판단과 데이터 분리**를 순서대로 배치
4. 636개 이벤트의 같은 시각 비교는 PPT에서 생략 가능하며 상세 보고서에 유지

| 왼쪽 핵심 근거 | 한 줄 설명 |
|---|---|
| **860건** | 2020~2022년 날짜가 CSV 행 순서대로 하루씩 증가 |
| **226쌍** | 시작보다 완료 시각이 먼저 기록된 업무가 존재 |

**오른쪽 권장 문구**

> **판단** 실제 날짜와 오류 수정 규칙을 확인할 수 없어 연도 일괄 치환을 보류
>
> **처리** 원본은 유지하고 분석 목적에 따라 데이터 분리
>
> 업무 흐름 **1,000건** · 개별 업무 시간 **3,151쌍** · 일반 경로 시간 **339건**

**삭제 권장**

- 하단의 `날짜 복원 근거가 없어 원본 유지 / 이후 분석은 목적별 표본으로 진행` 문구는 오른쪽 판단과 중복되므로 삭제
- `연도 치환·행 삭제 보류`는 오른쪽 판단에 포함하고 하단에서 중복 표기하지 않음

**반드시 남길 주의사항**

> 1970년 기록도 실제 날짜의 정확성이 검증된 것은 아님

**시각적 배치**

- 왼쪽 근거 카드 2개와 오른쪽 결론 카드 1개에 공간을 집중
- 검증 상세 수치는 보고서에 남기고 PPT에서는 `확인된 이상 → 보정 보류 → 표본 분리`가 먼저 보이도록 구성

### 5페이지 — 업무 흐름 분석

**조치: 유지**

- 원본 업무명과 한국어 설명이 함께 제시되어 있어 유용
- 수리 분기가 병렬 경로로 *동시에 반드시 수행되는 것처럼* 보이지 않게 `단일 또는 복합 가능` 주석 유지
- 도식이 이미 일반 927건과 예외 73건을 설명하므로 하단 해석 문장이 중복될 경우 간단히 처리

### 6페이지 — 반복 작업 분석

**조치: 유지**

- 복합 수리 91건과 `InternRepair` 반복 38건 그리고 실제 시각 순서 예시를 유지
- `반복 원인·재작업 여부는 미확인` 문구는 반드시 유지
- 하단 `다음으로 업무 시간과 전체 시간을 비교`는 발표자가 말할 내용이므로 공간이 부족하다면 삭제 가능

### 7페이지 — 개별 업무 시간과 전체 시간 비교

**조치: 유지**

- 중앙값 4분 · P90 404.8분 · 1시간 초과 194건 · 케이스 전체 시간 78.2시간/77.2시간 비교 유지
- 비교 단위가 `809 업무쌍` 대 `339 케이스`로 다르므로 표본 설명 보존
- `P90` 설명은 한 번만 표기

### 8페이지 — 전체 처리 시간 분석

**조치: 유지**

- 70.8% 흐름 시각화는 발표의 핵심이므로 확대 상태 유지
- 하단 `조사 전 대기가 전체 시간 합계의 70.8%`는 제목과 그래프에서 반복된다면 삭제 가능
- `70.8%는 절감 가능 비율이 아님`은 유지

### 9페이지 — 주요 대기 구간 분석

**조치: 유지**

- 분포 그래프와 54.5시간 · P90 195.7시간 · 24시간 초과 211/339건 유지
- 하단의 `24시간 초과 211/339건(62.2%)`가 그래프 옆 지표와 중복되면 삭제
- `24시간은 탐색 기준이며 운영 SLA가 아님`은 작은 주석으로 유지

### 10페이지 — 수리 유형별 비교 **[소폭 수정]**

**현재 문제**

- 위쪽 E 유형 **25.2시간**과 아래쪽 E 유형 **25.9시간**의 비교 표본이 서로 다름
- 처음 읽는 사람은 두 수치가 왜 다른지 즉시 알기 어려움

**권장 교체**

- 상단 카드 제목: **`E 유형 전체 · 수리 시작 전 대기`**
  - `143건 · 중앙값 25.2시간`
- 하단 표 제목: **`같은 내부 수리(InternRepair)만 수행한 요청 비교`**
  - B **25건 / 0.0시간**
  - E **127건 / 25.9시간**
  - P **8건 / 0.9시간**

**하단 해석 권장 문구**

> 같은 내부 수리 업무로 범위를 좁혀도 E 유형에서 긴 대기가 관찰됨

**유지할 주의사항**

> 수리 유형이 지연의 원인이라는 뜻은 아니며 P 유형은 표본이 8건으로 작음

**디자인**

- 그래프와 비교표는 유지
- 두 영역 제목만 명확히 구분하고 새로운 주석 박스를 추가하지 않음

### 11페이지 — 접수 채널과 담당자 분석

**조치: 유지**

- Web 중앙값 119분 · Letter 5분 · 채널별 1시간 초과율 유지
- 동일/다른 담당자 중앙값 4분/332분 유지
- `담당자가 다르다 = 실제 인수인계`로 단정하지 않는 주의사항 보존
- 하단 `차이 확인` 문장은 제목에서 반복되면 삭제 가능

### 12페이지 — 개선 방안

**조치: 유지**

- 세 문제에 대응하는 추가 기록과 조치의 3열 구조가 직관적임
- 하단 `해석`과 `해석 시 주의`를 한 줄로 축약 가능

**축약 문구**

> 추가 기록으로 실제 지연 원인을 확인한 뒤 필요한 조치를 시범 적용

- 추가 제안한 자재 부족이나 인력 과부하 등의 원인을 새로 쓰지 않음

### 13페이지 — 효과 검증과 분석 한계 **[중점 수정]**

**현재 문제**

- 성과 지표 · 계산식 · 5개 한계 · 하단 해석 박스가 한 화면에 동시에 등장
- 마지막 슬라이드인데 최종 성과 지표보다 계산 조건이 먼저 눈에 들어옴

**권장 구조**

**① 개선 과제별 성과 지표 — 왼쪽**

| 개선 과제 | 핵심 측정 지표 |
|---|---|
| 현장 조사 일정 | 조사 착수 지연 시간 · 예정 시각 초과 미착수율 |
| E 유형 수리 착수 | 수리 시작 전 대기 · 예정 시각 초과 미착수율 |
| Web·Letter 일정 조율 | `ArrangeSurvey` 1시간 초과율 · P90 |

**② 최종 성과 지표 — 오른쪽 가장 크게**

> **수리 요청 전체 처리 시간**
>
> **중앙값 · P90**

**③ 분석 한계 — 하단 1줄**

> 날짜 정확성 미검증 · 예정 시각 미기록 · 시간 분석 대상 339건

**삭제·이동 권장**

- 미착수율 계산식은 **상세 보고서**로 이동
- 한계 5개를 PPT에서 모두 열거하지 않음
- `예정 시각·지연 사유를 기록한 뒤 대기와 전체 완료 시간의 변화를 비교`는 상단의 메시지와 중복되므로 삭제
- `현재는 실제 지연 원인 미확인 / 개선 효과는 아직 검증 전`은 한 문장으로 압축하거나 발표자 설명에서만 활용

**반드시 명시할 점**

> 신규 지표는 추가 데이터 수집 이후 계산 가능하며 개선은 아직 실행·검증되지 않음

## 3. 슬라이드 전체의 디자인·텍스트 원칙

| 요소 | 수정 원칙 |
|---|---|
| 작은 분석 단계명 | 유지 · 모든 페이지에서 같은 위치 사용 |
| 메인 제목 | 한 페이지의 핵심 발견만 전달 · 가능하면 2줄 이내 |
| 설명 문장 | 제목과 같은 내용을 반복하지 않고 **왜 이 분석을 했는지**만 짧게 전달 |
| 본문 | 그래프 또는 표를 시선의 중심에 배치 |
| 하단 해석 | 그래프만으로 알기 어려운 **새로운 판단**이 있을 때만 유지 |
| 하단 주의사항 | 결과 해석을 바꾸는 핵심 한계만 표시 |
| 세부 공식·선정 과정 | 상세 분석 보고서와 노트북으로 이동 |
| 숫자 | **표본 수와 단위**가 빠지지 않도록 유지 |
| 컬러 | 현재의 청록·회색·검정 톤 유지 · 새 강조색 추가 금지 |
| 여백 | 삭제한 텍스트 공간은 차트 확대와 요소 간 간격 확보에 사용 |

### 문장 스타일 통일

- 본문 종결에 마침표를 사용하지 않음
- 문장 내 쉼표는 나열할 때만 사용
- 원본 `taskID`는 영어로 표기하고 필요하면 짧은 한국어 설명을 병기
- `병목`, `재작업`, `원인`, `절감효과`는 관찰 결과만으로 확정하지 않음
- 표본이 서로 다른 결과는 같은 그래프나 표에 합쳐서 직접 비교하지 않음

## 최종 판단

현재 자료는 **전면 재작업할 단계가 아님**

- **우선 작업** 13페이지 압축 → 4페이지 압축 → 10페이지 표본 제목 수정
- **나머지 페이지** 중복된 하단 설명만 필요한 만큼 삭제
- 최종 목표는 처음 보는 사람이 각 슬라이드에서 **왜 분석했는지 → 무엇을 발견했는지 → 그래서 무엇을 제안하는지** 바로 이해하는 것
